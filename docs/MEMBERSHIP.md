# Better Life 会员与收费方案

状态：产品设计稿，尚未开通收款、登录或会员权益。2026-10-03。

## 用户买到什么

用户为「把自己的问题整理成可执行计划，并随时找回来」付费。原书、全文检索、出处、基础收藏、PDF 和 Obsidian Vault 继续免费。

首页仍然让用户先问问题。拿到第一份有用的回答之后，再介绍会员；阅读原文、复制来源和下载 Vault 不弹付费拦截。避免用原书已有的免费内容制造付费门槛。

会员主文案：**遇到事，有一份自己的行动方案。**

辅助文案：结合指南整理下一步，保存问题和清单，换一台设备也能接着用。

## 额度规则

一次成功的生成扣 1 次。追问也扣 1 次，提交前说明。看原文、打开已保存回答、复制、下载 Vault 不扣次数。

- 回答校验失败、超时、用户取消、上游失败不扣用户额度；平台仍记录可能发生的模型成本。
- 书中依据不足的回答不扣用户额度，但计入请求频率和平台预算，避免无限空问。
- 同一用户、相同请求 ID 在 24 小时内重试返回原结果，不重复扣次数。
- 游客额度需要签名匿名标识、服务端持久计数和挑战验证；删除 Cookie 不能无限领取。当前内存 IP 限流不能承担该职责。
- 会员每日最多 30 次、每分钟最多 6 次，同时 1 个生成请求。月度余额、日限额、限速和平台预算都在服务端判定。
- 剩余额度不结转。30 天到期后回到免费权益，已保存内容仍可查看、导出和删除。
- 不提供「无限问」或终身会员。超额首先提示下一次额度更新时间；后续可试 ¥6 / 50 次补充包，有效期 90 天，无需自动扣款。
- 游客注册不会重置免费额度：已用 3 次从首期 10 次中扣除。

## 用户流程

1. 用户先体验完整的基础回答和原文依据。
2. 点击「保存到我的清单」时，说明登录能跨设备保存；基础复制保持免费。
3. 在需要追问、保存更多方案或免费额度用完时，展示套餐，清楚写明总价、有效期和次数。
4. 选择套餐 → 登录 → 确认订单（总金额、权益、到期规则）→ 支付 → 查询订单状态。
5. 服务端确认支付成功后开通，展示有效期、余额、订单号和入口。
6. 「我的会员」固定提供到期时间、额度更新日、订单、申请退款和联系入口。

首版采用一次购买到期制，没有自动续费。用户主动续购相同套餐，从已有 paid_until 延长；月付转年付采用「到期后生效」，不同时计费，不在首版做复杂折抵。购买补充包不延长会员期限。

## 收费系统设计

推荐为 GitHub Pages 保留静态前端，账号、问答额度和支付使用独立 HTTPS 服务端。数据库用 PostgreSQL，服务端统一管理登录会话、订单、额度和模型请求。未选择部署供应商前，不把特定套餐可用性写成事实。

首版登录建议邮箱验证码；手机号和微信登录可以后续添加。支付计划优先微信支付（桌面扫码、手机浏览器对应支付方式），能否开通要以实际商户主体和申请结果为准。支付宝作为后续补充。

支付平台官方文档尚未在本轮成功读取，因此下面是平台无关的系统要求，具体字段、证书、费率和准入要求在接入时以官方文档重新核对；没有开通支付账户，也没有向支付平台发送订单。

### 数据实体

| 实体 | 核心字段 | 必须保证 |
| --- | --- | --- |
| users | id、邮箱、创建时间、删除时间 | 邮箱唯一，用户标识不暴露个人信息 |
| sessions | 用户、token_hash、expires_at、revoked_at | HttpOnly / Secure Cookie，会话可撤销 |
| plans | 套餐码、版本、金额分、时长、额度规则 | 购买时锁定版本，后改价格不改旧订单 |
| orders | 用户、套餐快照、金额、币种、状态、支付单号 | 价格只由服务端确定，业务订单号唯一 |
| payment_events | 支付平台、事件 ID、验签结果、接收时间 | 回调去重、验签、验商户、验金额、验币种 |
| entitlements | 用户、来源订单、生效/到期时间 | 同一成功订单只授予一次权益 |
| quota_periods | 用户、起止时间、总额度、已用、预占 | 数据库原子操作，禁止并发超扣 |
| generation_requests | 用户、请求 ID、状态、预占额度、token 用量、成本 | 幂等，过期请求可释放预占额度 |
| quota_ledger | grant / reserve / consume / release / revoke | 不删除流水，修正用反向流水 |
| saved_answers | 用户、原书版本、引用、回答、创建时间 | 用户主动保存；支持删除与导出 |
| refunds | 订单、退款金额、状态、平台退款 ID | 累计退款不超过实付，同步撤销权益 |

问题默认不入持久存储；用户主动保存才保存问题和答案。统计只记录状态、次数、耗时、token 用量，不采集问题正文。生产日志不能含密钥和完整个人问题。

### 订单与退款状态

订单：created → pending → paid；未付订单可 cancelled 或 expired。paid → refund_pending → partially_refunded / refunded。退款失败回到退款申请前的 paid / partially_refunded，不假装退款已到账。

只有验签通过的服务端回调或服务端向支付平台查单的结果能变更 paid。前端「支付完成」按钮只触发查单。重复回调返回已处理；晚到的支付回调不直接丢弃，先查单核对实际支付情况。

会员状态：scheduled / active / expired / revoked。退款撤销对应订单提供的权益；延后生效的后续订单仍保持原购买时段，不能自动多送或扣减时间。补充包只撤销其未用余额，已使用部分在退款审核中单独核算。

首版承诺「购买后 7 天内且付费权益未使用，可全额申请退款」作为拟定的产品政策；有使用、故障争议或特殊情况人工处理。它不是法律适用结论。上线前核对经营主体所在地和服务条款，页面展示实际可执行的规则。

### 问答扣次的事务边界

1. 校验会话、平台预算、速率和请求幂等键。
2. 在事务中锁定额度周期，原子预占 1 次，并写入 reserve 流水。
3. 事务外调用 DeepSeek。每次调用记录 token 用量和模型费用，所有请求都计入平台预算。
4. 回答结构、引用和完成状态全部有效时，在事务中消耗预占，写 consume；其余写 release。
5. 断连/服务重启的悬挂请求由恢复任务查状态，超过最长执行期释放一次；同一请求不能同时 consume 和 release。
6. 生成已成功但前端断线：保留可重取的结果、保持一次扣次，不能再次生成再收费。

初始预算假设：平台每天模型支出上限 ¥50，80% 提醒，100% 暂停新生成；已保存内容和原文继续可用。预算在持久存储中为每个请求预留最坏费用，结束后按 usage 结算，避免并发越限。生产预算与账户余额告警是两层措施。

## 推进与验收

第一阶段：当前真实问答 + 免费 Vault；补上服务端 usage 统计，不收费。

第二阶段：登录、主动保存、跨设备、追问、额度流水、Markdown 导出；用测试支付渠道验证订单和退款。

第三阶段：开放 ¥19 / 30 天，观察 14 天：首次有效回答率、保存率、7 天复访率、付费转化率、退款率、每付费用户生成成本。定义数据口径：付费转化 = 期间首次付费人数 / 同期看到价格页且未付费的独立登录人数。

第四阶段：有重复使用证据和真实成本数据后开放 ¥129 年付，测试补充包。

必须通过的验收：篡改前端价格无效；伪造成功回跳不开通；重复回调不开通两次；两个并发问答不超扣；超时不扣次；成功断线重取只扣一次；到期保留历史导出；申请退款和实际到账区分；退款撤权与额度正确；账号 A 无法读取账号 B 的记录；密钥不出现在静态包、日志或客户端网络响应中。
